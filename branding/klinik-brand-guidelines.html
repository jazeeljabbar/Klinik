01 · Brand overview

Clinical precision.
Human warmth.

KliniK is an AI-powered acne analysis platform by HOPELABSAI Solution Private Limited. The brand sits at the intersection of clinical authority and approachable care — users are vulnerable when sharing skin concerns, so every touchpoint must feel trustworthy yet never cold.

The name's symmetrical K bookends evoke diagnostic precision, while the lowercase interior ("lini") softens the clinical feel. The coral crosshair on the first "i" is the brand's signature element — a diagnostic motif that doubles as the app icon and favicon.

06 · Tone & voice

Empathetic authority

Users sharing skin images are in a vulnerable state. The tone must balance clinical credibility with genuine care. Never alarmist, never dismissive.

✓ Do

"Moderate acne detected. Multiple blemishes present that may benefit from a targeted treatment approach."

"Your analysis is ready — here's what we found."

"AI-powered skin condition assessment"

✗ Don't

"WARNING: Severe acne problem detected! Seek treatment immediately!"

"Bad news — your skin has issues."

"Our AI diagnoses your skin disease"

Medical disclaimer: Always present the medical disclaimer prominently. Use language like "educational purposes" and "AI-powered assessment" — never "diagnosis" or "medical advice." The disclaimer should appear on every results page and in the footer.

07 · Production readiness checklist

From prototype to production

Key changes from the current "SKIN AI" prototype to make KliniK feel production-ready.

  • Replace the stock hero image with a custom illustration or a more abstract, privacy-respecting visual. The current photo of a person holding a phone feels generic — consider an abstract skin-texture pattern or a stylized diagnostic scan animation instead.
  • Add a loading/analysis state with a branded animation. The crosshair motif spinning or pulsing over a blurred version of the uploaded image gives the user confidence something is happening.
  • Implement proper image upload UX — show upload progress, file validation feedback, and a clear preview with crop/rotate options before analysis. The current drag-and-drop zone needs tighter visual polish.
  • Add smooth page transitions between upload → analyzing → results. A slide or fade transition keeps the experience feeling intentional rather than abrupt.
  • Design the recommendation section properly — the current yellow sidebar with heart icon feels disconnected from the analysis. Integrate it as a card within the results flow with clear visual hierarchy.
  • Build a proper onboarding flow for first-time users explaining what the tool does, how data is used, and setting expectations about accuracy limitations.
  • Add a history/dashboard view for logged-in users to track skin progress over time — this is the feature that turns a one-time tool into a retention product.
  • Ensure WCAG 2.1 AA compliance — the current orange-on-white severity labels likely fail contrast requirements. Use the navy/coral palette which has been chosen for accessibility.
  • Add proper error states — what happens when the image is too blurry, not a face, or the API fails? Each state needs a designed screen with clear next steps.
  • Add social proof — total analyses performed, accuracy stats, or testimonials. A counter like "127,000+ skin analyses completed" builds trust immediately.
  • SSL certificate, custom domain, and proper meta tags with OpenGraph images using the KliniK branding for social sharing.
  • Add a privacy policy page explaining how uploaded images are processed, stored, and (if applicable) used for model improvement. This is critical for user trust in a health-adjacent product.
08 · Spacing & layout

Spatial rhythm

Use an 8px grid system throughout. Key spacing values:

8px — tight (icon padding, inline gaps)
16px — compact (card padding, between related items)
24px — default (section gaps, card margins)
32px — comfortable (between components)
48px — generous (between major sections)
80px — dramatic (page section padding)

Border radius system: 4px for small elements (badges, tags) · 8px for inputs and small buttons · 12px for buttons and cards · 16px for modal/panel containers · 20px for hero sections and large containers. Never mix rounded and sharp corners within the same component group.
